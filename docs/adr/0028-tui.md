# ADR-0028: A zero-dependency terminal UI

* **Status**: accepted (v0.17)
* **Context**: Operators want an at-a-glance terminal view: open task
  count, top owners, webhook DLQ depth, recent activity. We don't
  want to add `urwid`, `textual`, or `rich` to the runtime — those
  pull in 5–20 MB of transitive deps and make the CLI launch slower.
* **Decision**: Hand-rolled ANSI renderer in `labflow/tui.py`, no
  third-party deps, prints to stdout via simple escape codes.
  `labflow tui --once` prints one snapshot and exits (the form used
  by tests and by users piping into `less`); the default loop polls
  every second and exits on `q`.

## What's on the screen

* Header: `LabFlow {version} — team {slug}`
* Task counts split by status (open / in-progress / blocked / done)
* Top 5 owners by open + in-progress count, with a unicode bar chart
* Webhook DLQ counters
* 12-week activity strip rendered with `· ░ ▒ ▓ █`

## Why not curses

* `curses` doesn't run on Windows out of the box (Python
  `windows-curses` shim required).
* Plain ANSI works in any terminal emulator, in tmux, in SSH, in CI
  log viewers, in `script` recordings, in screenshots embedded in
  docs.
* Easy to test: `tui.run(once=True, out=StringIO())` returns a string
  we can assert against.

## What we sacrifice

* No mouse, no scrollback. The screen is one snapshot — for deeper
  drill-down operators use the REST API or HTMX UI.
* No partial redraw. We clear-and-redraw the whole screen each
  refresh. At 1 Hz this is invisible; we'd revisit only if anyone
  asks for sub-second refresh.
